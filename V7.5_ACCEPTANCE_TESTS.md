# V7.5 Acceptance Test Map

Use one major test at a time. Report a failure by major test, letter, and step (example: `Test 6C-3 failed`).

## Test 1 — Login and Role Permissions
A. Admin login and navigation
B. Chief permissions and Admin-account restrictions
C. Officer permissions
D. Engine Boss login redirect and Wildland-only navigation
E. Engine Boss management of any active deployment

## Test 2 — Member Management
A. Create one member
B. Batch add multiple members
C. Edit a member and verify custom qualifications/certifications are preserved
D. Add/edit/view/delete member documents and certifications
E. Verify issue/expiration/source/verification/external-link fields
F. Red Card upload and status

## Test 3 — Member NFC and Protected Information
A. Public member profile privacy
B. Medical one-view PIN unlock
C. Red Card status and one-view PIN unlock of the full card
D. Failed PIN/lockout behavior

## Test 4 — Wildland Deployment
A. Create deployment
B. Add/remove crew
C. Engine Boss manages an active deployment created by another user
D. End deployment
E. Reopen deployment with reason and preserved history

## Test 5 — Time and Apparatus Tracking
A. Individual crew clock
B. Crew-wide clock
C. Apparatus clock, mileage, and engine hours
D. Combined crew + apparatus clock
E. Correct completed crew time while deployment remains active

## Test 6 — Deployment Forms
A. Generate and preview CTR / SF-261
B. Edit every application field exposed in the CTR editor
C. Save a new CTR PDF version with the deployment
D. Generate/edit/preview/save OF-288 for a selected member
E. Generate/edit/preview/save OF-286 for apparatus
F. Verify previous versions remain with the deployment
G. Verify form generation and overrides in Audit Log

## Test 7 — Apparatus and Apparatus NFC
A. Apparatus profile
B. NFC URL while apparatus is available
C. Authenticated NFC tap while actively deployed redirects directly to deployment
D. Deployment-entry controls are usable after redirect

## Test 8 — Security, Audit, Backup, and Reliability
A. Approved-device lifecycle
B. Access auditing
C. Feedback workflow
D. Backup/restart
E. Error handling
F. Final desktop restart and regression pass

After the desktop pass, run the separate mobile acceptance series. Actual phone/NFC testing remains last.
